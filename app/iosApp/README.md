# iOS App Module

The `app:iosApp` module is the native SwiftUI/UIKit shell for NoteDelight. It consumes the dynamic `iosComposeKit` Kotlin framework and SQLCipher through Kotlin's Swift Package Manager integration.

## Structure

```text
app/iosApp/
├── iosApp/                              # Swift application sources
├── Note Delight Unit-Tests/             # Xcode unit tests
├── iosApp.xcodeproj/                    # Open and build this project
├── KotlinMultiplatformLinkedPackage/    # Generated Swift package used for linkage
└── fastlane/                            # App Store automation
```

The repository no longer uses CocoaPods. Do not generate a Podfile, podspec, Pods directory, or Xcode workspace.

## Integration

The Xcode project contains a Gradle build phase generated by:

```bash
XCODEPROJ_PATH=app/iosApp/iosApp.xcodeproj \
GRADLE_PROJECT_PATH=:app:ios-kit \
./gradlew :app:ios-kit:integrateEmbedAndSign :app:ios-kit:integrateLinkagePackage
```

During an Xcode build, the phase invokes `:app:ios-kit:embedAndSignAppleFrameworkForXcode`. Kotlin's linkage package makes SwiftPM products used by Kotlin, including SQLCipher, available to the application.

`ENABLE_USER_SCRIPT_SANDBOXING` must remain `NO` because the Gradle build phase writes generated framework output. `SQLITE_HAS_CODEC=1` must remain defined so Swift can access SQLCipher APIs such as `sqlite3_key`.

## Building

Open and run the project:

```bash
open app/iosApp/iosApp.xcodeproj
```

Before the first iOS run from Android Studio after a fresh checkout or branch switch, run:

```text
Tools > Swift Package Manager > Resolve Dependencies
```

Android Studio keeps its own Xcode DerivedData and SwiftPM resolution state. Recreating the iOS run configuration or resolving packages in Xcode does not populate that separate state. If it is empty, Android Studio can report `Missing package product 'KotlinMultiplatformLinkedPackage'` even while the same project builds in Xcode.

Build from the command line:

```bash
xcodebuild \
  -project app/iosApp/iosApp.xcodeproj \
  -scheme iosApp \
  -destination 'generic/platform=iOS Simulator' \
  ARCHS=arm64 \
  CODE_SIGNING_ALLOWED=NO \
  build
```

Build the Kotlin framework directly:

```bash
./gradlew :app:ios-kit:linkDebugFrameworkIosSimulatorArm64
```

## Testing

Run the Xcode unit tests on an available simulator:

```bash
xcodebuild \
  -project app/iosApp/iosApp.xcodeproj \
  -scheme iosApp \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' \
  CODE_SIGNING_ALLOWED=NO \
  test
```

`Note_Delight_Unit_Tests.testCipherChecker` verifies that the linked SQLCipher binary is usable and reports the expected version.

## Distribution

Fastlane builds `iosApp.xcodeproj` directly:

```bash
cd app/iosApp
fastlane appstore_build_gym_lane
```

Signing files and App Store credentials remain local or encrypted in CI.
